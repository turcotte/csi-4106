Definition

(Russell and Norvig 2020, 63)

When the correct action to take is not immediately obvious, an agent may need to plan ahead: to consider a sequence of actions that form a path to a goal state. Such an agent is called a problem-solving agent, and the computational process it undertakes is called search.

Terminology

The definition of an agent in artificial intelligence (AI) shares some similarities with the psychological definition, but there are key distinctions. In AI, an agent is an autonomous entity that perceives its environment through sensors and acts upon it using actuators to achieve specific goals. Both definitions involve perception, decision-making, and action.

However, while psychological agents are human or biological and involve complex cognitive and emotional processes, AI agents are computational and operate based on algorithms designed to maximize certain performance measures or achieve predefined objectives. The focus in AI is more on the technical implementation of these processes, whereas in psychology, the emphasis is on understanding the cognitive and motivational aspects of agency.

The concept of agentic design in software engineering and artificial intelligence has experienced a resurgence in popularity.

An agent is an entity that performs actions. A rational agent selects actions expected to achieve the best outcome, given its information and performance measure. Conceptually, an agent perceives its environment through sensors and interacts with it using actuators.

Environment Characteristics

  • Observability: Partially observable, or fully observable
  • Agent Composition: Single or multiple agents
  • Predictability: Deterministic or non-deterministic
  • Decision Dependency: Episodic or sequential
  • Temporal Dynamics: Static or dynamic
  • State Representation: Discrete or continuous

The characteristics of an environment influence the complexity of problem-solving.

  • A fully observable environment allows the agent to detect all relevant aspects for decision-making.

  • In a deterministic environment, the agent can predict the next state based on the current state and its subsequent action.

  • Episodic environments involve independent decisions: an action in one episode does not affect later episodes. Classifying independent images is an example.

  • Sequential environments require considering how an action affects future decisions. The 8-puzzle and chess are examples. A state can summarize all relevant history without making the task episodic.

  • A dynamic environment can change independently while the agent deliberates. A static environment does not change during deliberation, but the agent’s actions can still change its state.

  • Chess serves as an example of a discrete environment, with distinct states and actions. Discrete spaces can be finite or countably infinite. In contrast, an autonomous vehicle operates within a continuous-state and continuous-time environment.

In this lecture, environments are assumed to be: fully observable, single agent, sequential, deterministic, static, and discrete.

Problem-Solving Process

Search: The agent simulates possible sequences of actions in a model to find a path to a goal state. A successful sequence is a solution, which the agent can then execute.

A precise formulation facilitates the development of reusable code.

Under these assumptions, a solution, when one exists, can be expressed as a fixed sequence of actions rather than a policy that branches on uncertain outcomes.

  • Sequential: Each action changes the state and can affect which subsequent actions lead to the goal. The state representation retains the information needed to predict future transitions.
  • Single Agent: There is no interaction with other agents that could introduce variability.
  • Fully Observable: The agent has complete information about the environment, allowing for precise decision-making.
  • Deterministic: The outcome of actions is predictable, with no randomness affecting the result.
  • Static: The environment does not change independently while the agent plans; executing an action still changes the state.
  • Discrete: States and actions are distinct alternatives that can be considered separately; the space need not be finite.

This formulation connects familiar graph-traversal algorithms with planning: the search selects a sequence in the model before the agent carries it out in the environment.

Search Problem Definition

  • A collection of states, referred to as the state space.

  • An initial state where the agent begins.

  • One or more goal states that define successful outcomes, recognized by a goal test.

  • A set of actions available in a given state s.

  • A transition model that determines the next state based on the current state and selected action.

  • An action cost function that specifies the cost of performing action a in state s to reach state s'.

Definitions

  • A path is a sequence of states connected by actions; it can be recorded as the action sequence or the resulting state sequence.
  • A solution is a path that connects the initial state to the goal state.
  • An optimal solution is the path with the lowest cost among all possible solutions.

In certain problems, multiple optimal solutions may exist. However, it is typically sufficient to identify and report a single optimal solution. Providing all optimal solutions can significantly increase time and space complexity for some problems.

We assume that the path cost is the sum of the individual action costs, and all costs are positive. The state space can be conceptualized as a graph, where the nodes represent the states and the edges correspond to the actions.

Code 
import random
import matplotlib.pyplot as plt
import numpy as np

random.seed(58)

def is_solvable(tiles):
    # Count the inversions in the flattened list of tiles (excluding the blank space).
    # Assumption: board is square and width is odd.
    inversions = 0
    for i in range(len(tiles)):
        for j in range(i + 1, len(tiles)):
            if tiles[i] != 0 and tiles[j] != 0 and tiles[i] > tiles[j]:
                inversions += 1
    return inversions % 2 == 0

def generate_solvable_board():
    # Generate a random board configuration that is guaranteed to be solvable
    tiles = list(range(9))
    random.shuffle(tiles)
    while not is_solvable(tiles):
        random.shuffle(tiles)

    return tiles

def plot_board(board, title, num_pos, position):
    ax = plt.subplot(1, num_pos, position)
    ax.set_title(title)
    ax.set_xticks([])
    ax.set_yticks([])

    board = np.array(board).reshape(3, 3).tolist() # Reconfigure the grid to be 3x3

    # Use a color map to display the numbers
    cmap = plt.cm.plasma
    norm = plt.Normalize(vmin=-1, vmax=8)

    for i in range(3):
        for j in range(3):
            tile_value = board[i][j]
            color = cmap(norm(tile_value))
            ax.add_patch(plt.Rectangle((j, 2 - i), 1, 1, facecolor=color, edgecolor='black'))
            if tile_value == 0:
                ax.add_patch(plt.Rectangle((j, 2 - i), 1, 1, facecolor='white', edgecolor='black'))
            else:
                ax.text(j + 0.5, 2 - i + 0.5, str(tile_value),
                        fontsize=16, ha='center', va='center', color='black')

    ax.set_xlim(0, 3)
    ax.set_ylim(0, 3)

  • Each state can be represented as a list containing the numbers 0 to 8. Each number corresponds to a tile, and its position in the list reflects its location in the grid, with 0 denoting the blank space.

  • The initial state is a permutation of the numbers 0 to 8.

  • Actions move the blank left, right, up, or down by swapping it with an adjacent tile. These directions describe the blank’s movement, not the numbered tile’s movement.

  • A path would be a sequence of actions, say left, left, up.

  • The transition model maps a given state and action to a new state. Not all actions are feasible from every state; for instance, if the blank space is at the edge of the grid, only certain moves are possible, such as down, up, or left.

  • The goal state is achieved when the list is ordered from 1 to 8, followed by 0, indicating that the tiles are arranged correctly. How many goal states are there? This formulation specifies one goal state, although another problem could permit several.

  • A solution would be a valid path transforming an initial state into a goal state.

  • Each action incurs a cost of 1.

How many possible states are there?

There are 9! = 362,880 arrangements of the eight tiles and the blank. Only half, 9!/2 = 181,440, are reachable from a fixed initial state. Exhaustive graph search is feasible at this scale.

How many states are there for the 15-Puzzle?

There are 16! = 20,922,789,888,000 arrangements of the fifteen tiles and the blank, with 16!/2 = 10,461,394,944,000 reachable from a fixed initial state: about 10.46 trillion. This much larger space motivates more selective search. See the 15-puzzle solver’s state counts.

Are all the boards solvable?

  • An 8-puzzle board is solvable if it has the same inversion parity as the goal state.

  • An inversion is a pair of tiles (excluding the blank) that are in the wrong order relative to each other, when reading the board as a one-dimensional list (left-to-right, top-to-bottom).

  • When the goal is the ordered sequence from 1 to 8, there are no inversions, and therefore parity is even.

  • See Archer (1999) or Slider Puzzle, Princeton

For an odd-width board such as the 3×3 puzzle, two arrangements are connected by legal moves exactly when their inversion parities agree. The simple inversion-only rule does not extend to even-width boards: the 4×4 puzzle also requires the blank’s row in the solvability test.

Code 
from itertools import permutations

def count_even_odd_parity():
    even_count = 0
    odd_count = 0

    for perm in permutations(range(9)):  # 0 represents the blank
        inversions = 0
        for i in range(9):
            for j in range(i + 1, 9):
                if perm[i] != 0 and perm[j] != 0 and perm[i] > perm[j]:
                    inversions += 1
        if inversions % 2 == 0:
            even_count += 1
        else:
            odd_count += 1

    return even_count, odd_count

Search Tree

The search algorithms construct nodes representing states reached by particular paths. A node may retain its parent, the action used to reach it, and the path cost. In the implementations below, a pair (state, path) stores the state and the preceding state sequence.

The state-space graph describes the problem: its vertices are states and its edges are actions. The search tree describes paths considered during search. Several paths can reach the same state, so the same state can occur at several tree nodes. The algorithms below use repeated-state detection, making them graph-search implementations; they do not retain every repeated occurrence in the conceptual tree.

A search tree records possible paths from the initial state. Each node records a state reached along a particular path, and each edge represents an action. Different nodes can represent the same state.

Search Tree

An example of a search tree for the 8-Puzzle. The solution here is incomplete.

Search Tree

  • The root of the search tree represents the initial state of the problem.

  • Expanding a node generates successor states by applying the available actions to its state.

  • The result of an action is the new state achieved after applying that action to the current state.

  • Every node except the root has a parent, including leaf nodes. Expanding a node may generate children.

A distinctive feature of a search algorithm is its method for selecting the next node to expand.

Frontier

Any state corresponding to a node in the search tree is considered reached. Frontier nodes are those that have been reached but have not yet been expanded. Above, there are 10 expanded nodes and 11 frontier nodes, resulting in a total of 21 nodes that have been reached.

Frontier

These schematic graphs illustrate how a frontier changes as nodes are expanded. Expanding a green node generates its successors: newly reached states enter the frontier, while already reached states are not added again in the graph-search implementations below. Purple nodes have already been expanded. The drawn grid positions do not encode 8-puzzle tiles or determine which puzzle moves are legal.

Auxiliary function implementing the goal test.

expand

def expand(state):
    """Generates successor states by moving the blank tile in all possible directions."""
    size = int(len(state) ** 0.5)  # Determine puzzle size (3 for 8-puzzle, 4 for 15-puzzle)
    idx = state.index(0)  # Find the index of the blank tile represented by 0
    x, y = idx % size, idx // size  # Convert index to (x, y) coordinates
    neighbors = []

    # Define possible moves: Left, Right, Up, Down
    moves = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    for dx, dy in moves:
        nx, ny = x + dx, y + dy
        # Check if the new position is within the puzzle boundaries
        if 0 <= nx < size and 0 <= ny < size:
            n_idx = ny * size + nx
            new_state = state.copy()
            # Swap the blank tile with the adjacent tile
            new_state[idx], new_state[n_idx] = new_state[n_idx], new_state[idx]
            neighbors.append(new_state)
    return neighbors

Are there 8-Puzzle boards that have no solutions?

The solvability of the 8-puzzle depends on the number of inversions in the initial state. An inversion is a pair of tiles where a higher-numbered tile precedes a lower-numbered tile when the puzzle is viewed as a sequence (excluding the blank tile).

If the initial state and the goal state do not have the same inversion parity, then the board has no solution.

If the frontier becomes empty (no more nodes to be expanded), the problem has no solution.

print_solution

def print_solution(solution):
    """Prints the sequence of steps from the initial to the goal state."""
    size = int(len(solution[0]) ** 0.5)
    for step, state in enumerate(solution):
        print(f"Step {step}:")
        for i in range(size):
            row = state[i*size:(i+1)*size]
            print(' '.join(str(n) if n != 0 else ' ' for n in row))
        print()

Cycles

A path that revisits the same states forms a cycle.

Allowing cycles would render the resulting search tree infinite.

To prevent this, we monitor the states that have been reached, though this incurs a memory cost.

Breadth-first search

Breadth-first search

from collections import deque

Breadth-first search (BFS) employs a queue to manage the frontier nodes, which are also known as the open list.

Breadth-first search

def bfs(initial_state, goal_state):

    frontier = deque()  # Initialize the queue for BFS
    frontier.append((initial_state, []))  # A node: (state, preceding states)

    reached = set()
    reached.add(tuple(initial_state))

    expanded = 0  # Count non-goal nodes whose successors are generated

    while not is_empty(frontier):
        current_state, path = frontier.popleft()

        if is_goal(current_state, goal_state):
            print(f"Nodes expanded: {expanded}")
            return path + [current_state]  # Return the successful path

        expanded += 1

        for neighbor in expand(current_state):
            neighbor_tuple = tuple(neighbor)
            if neighbor_tuple not in reached:
                reached.add(neighbor_tuple)
                frontier.append((neighbor, path + [current_state]))

    return None  # No solution found

BFS selects nodes in nondecreasing depth because the frontier is a first-in, first-out queue. With equal action costs, the first path that reaches a state is a least-cost path to that state, so later occurrences can be discarded. Unequal action costs break the equivalence between fewest actions and least cost.

The reached set contains states in the frontier as well as expanded states. The expanded counter increases only when a non-goal node’s successors are generated; selecting a goal does not increase it. The returned solution is a sequence of states, including both endpoints, so its number of moves is len(solution) - 1.

Find a path with the fewest actions. This is a least-cost solution when all action costs are equal, as in the 8-puzzle.

Depth-First Search

def dfs(initial_state, goal_state):

    frontier = [(initial_state, [])]  # A node: (state, preceding states)

    reached = set()
    reached.add(tuple(initial_state))

    expanded = 0

    while not is_empty(frontier):
        current_state, path = frontier.pop()

        if is_goal(current_state, goal_state):
            print(f"Nodes expanded: {expanded}")
            return path + [current_state]  # Return the successful path

        expanded += 1

        for neighbor in expand(current_state):
            neighbor_tuple = tuple(neighbor)
            if neighbor_tuple not in reached:
                reached.add(neighbor_tuple)
                frontier.append((neighbor, path + [current_state]))

    return None  # No solution found

Depth-first search (DFS) uses a last-in, first-out stack. Newly generated nodes are selected before older alternatives, so the search follows a branch deeply before returning to other frontier nodes. The successor order matters: because expand lists left, right, up, down and the stack removes the last entry first, DFS tries the last newly added successor first.

When does the deepening process halt?

It stops following a branch when a goal is found or no new successor can be added, because there are no available actions or all successors have already been reached.

What happens next?

The algorithm pops the most recently added remaining frontier node. The stored path records how that alternative was reached; the code does not undo moves on a shared board.

If that node also has no new successors, the algorithm continues with the next stack entry. Repeated-state detection prevents cycles from continually adding the same states.

Will Depth-First Search (DFS) invariably yield sub-optimal solutions?

No. DFS can return an optimal solution if it encounters one first, but it provides no guarantee that the first solution has the fewest actions or lowest cost.

Is it possible for DFS to discover solutions superior to the optimal solution?

Certainly not; such solutions would either be invalid (involving impossible moves) or indicate an error in your estimation.

Does this imply that depth-first search (DFS) has no practical applications?

When is it appropriate to use DFS?

Breadth-first search (BFS) expands its frontier systematically in all directions, leading to rapid growth in memory requirements.

DFS often has a smaller frontier because it follows one branch before trying alternatives. However, the code shown here retains every reached state and copies paths into frontier entries. Its total memory is therefore not limited to the active branch, and a small frontier alone does not establish low total memory usage.

The usual small-memory description of DFS applies to implementations that retain the active path and pending alternatives, without a global record of all reached states. Such backtracking implementations can be useful when systematically exploring possible solutions. Their duplicate-handling and termination properties differ from those of the graph-search code above.

The programming language Prolog uses depth-first backtracking to search for answers. It can enumerate answers, but an infinite branch can prevent it from reaching other answers.

Completeness means finding a solution whenever one exists. Both graph-search implementations shown here are complete on a finite reachable state space because each state is added at most once. BFS also finds a finite-depth solution with finite branching in an infinite space; DFS can instead follow an infinite branch indefinitely.

These numerical results apply to the specified initial board and successor order. Expansion counts describe search effort, not elapsed time or peak memory; different boards or move orders can change the comparison substantially.

Depth-limited and iterative deepening search would be alternative uninformed search algorithms.

Heuristic functions use additional knowledge to estimate the remaining cost to a goal and guide search. They are the focus of the next lecture.
